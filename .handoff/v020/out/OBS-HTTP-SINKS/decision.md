| D371 | Query-log delivery to additional sinks (V2-OBS contract 6) | `querylog.sinks` (hot cluster setting, at most 8) adds destinations beside the primary `querylog.sink`. The one collector applies exclusions and the privacy mode once, stamps the ID, publishes to the tail, then offers the same immutable event without waiting to one bounded queue per sink (default 10,000; overflow is dropped for that sink and counted in `kudurru_querylog_dropped_total{stage="sink",sink}`). Each sink has its own goroutine, batch policy, attempt timeout and attempt budget; a batch is rewritten only after an error the sink marks as not applied (`querylog.Retryable`), otherwise dropped, and never replayed or moved. The privacy transform thus runs before every sink queue; `nothing` offers no per-query event and events carry no wire data (raw dnstap stays a separate audited override). Sinks follow D266: each prepared route holds a reference per sink (bundle release hook on SQLite, the reload subscriber on Kubernetes); an unchanged entry keeps its running sink; a new one is opened by its first event from its own goroutine, with backoff, and never backfilled; an unreferenced one retires behind the events already queued, drains at most five seconds and closes. Where requests do not hold their route (the reload subscriber of the Kubernetes driver), a query that read the replaced route just before the swap can reach a sink that has already retired: it is never handed to the entry's new sink, because a route's privacy mode and its sinks are one captured decision, and it is counted as dropped while the name is still configured; for a removed name nothing was owed and nothing is counted. At shutdown the sinks share the collector's five-second bound; a sink that did not drain is logged by name, apart from the local flush. ClickHouse and Loki are direct sinks on this host (`type: clickhouse`, `type: loki`) built on the standard library HTTP client, without an SDK: one POST per batch on its own connection (`INSERT ... FORMAT JSONEachRow` with `wait_end_of_query`; `/loki/api/v1/push` in JSON), gzip by default, redirects never followed. An HTTP sink marks a batch as retryable only when no connection was established or the destination answered 408, 429 or 5xx (`Retry-After` honored up to the host's 30 s cap); every other answer, and a request that was sent and got no answer, drops the batch. A 5xx is not proof that nothing was stored (a gateway's 502 or 504, a ClickHouse insert that failed part way); its repeat is accepted because the documented ClickHouse table deduplicates (`non_replicated_deduplication_window`) and Loki drops identical entries, and `attempts: 1` turns it off. A body of 64 KiB or more asks for `100 Continue` (at most 2 s), and the client's connections hide the write error of a peer reset (EPIPE, ECONNRESET) so that an answer sent before the reset is read: ClickHouse sends `100 Continue`, then refuses a wrong password and resets the connection under the body; a 2xx to a cut body is an unknown outcome. Both types export one flat JSON record per query, built from the event after the privacy transform; its field names are a contract with the documented ClickHouse table and with LogQL queries. Loki streams carry only the fixed labels of the settings, `node` and `status_class`; client, client name, domain, query type, status and trace ID are structured metadata. Settings hold credential references only (`passwordRef`, `bearerTokenRef`, `caRef`, each at most the resolver's 64 KiB, refused with a message that says so): a file or environment variable must be granted by the node's own `credentials.allowedFiles` or `credentials.allowedEnvironment`, and a Secret must be in the server's namespace and carry the label `kudurru.io/query-log-sink: "true"`. A grant is not bound to a destination: whoever may change the settings can have a granted value sent to any URL, so the grants are documented as being for credentials made for these destinations. A reference is read when the sink opens and again after a 401 or 403; a changed value makes the refused batch retryable, which is how a rotation is picked up. Errors report the status and, for ClickHouse, the numeric exception code, never a response body. dnstap to DNS-collector stays the path for other destinations and wire-level consumers. | A slow exporter must not stall DNS, local SQLite persistence or live tails, and the collector had one queue and one destination. Direct ClickHouse/Loki sinks are required v0.2 scope, need no second process and export exactly what the privacy mode keeps; an SDK would threaten the binary budget (D138, D260). `querylog.sinks` is a setting the API can change, and the server can read its own keys: without the node grants and the Secret label, whoever may change settings could have a file or a Secret of the server's namespace presented to a destination of their choice. One connection per batch makes "nothing was sent" and "outcome unknown" exact.
