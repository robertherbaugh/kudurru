| D396 | IAM writers for local accounts, ServiceAccounts and IdentityProviders | The complete SQLite runtime adds reviewed commands built like D294: `PATCH`/`DELETE /iam/users/{name}` (display name, groups, disabled; delete), `POST /iam/serviceaccounts`, `PUT`/`DELETE /iam/serviceaccounts/{namespace}/{name}`, `POST /iam/serviceaccounts/{namespace}/{name}/tokens`, `POST /iam/identityproviders` and `PUT`/`DELETE /iam/identityproviders/{name}`, plus item reads of both kinds on both drivers. Create is create-only and never adopts; replace and delete need the exact UID and resourceVersion and the API manager; the built-in admin, other managers and a service account with private bootstrap authority are refused by replace, delete and token issuance alike. Each command checks permission and CSRF on the original view before the body, decodes strictly, then reverifies the original raw proof for every attribute in one current command that stages the object through `security.Apply`/`security.Delete` (account or provider floor) and deletes the tokens the change ends, with the object audit row. A group change, disable or delete ends the account's sessions and deletes its tokens; enable restores none. Token issuance for a service account needs `serviceaccounts.write` and `tokens.write`, the exact account UID and an enabled, API-owned account without bootstrap authority; the token expires no later than the caller's own API token (as `POST /auth/tokens`) and within `auth.tokens.maxLifetime`; the token must authenticate from its stored form in the transaction; the secret is only in the 201 answer. Provider objects carry a credential reference, never a value; an id of the configuration file cannot be created. `GET /auth/status` reports `capabilities.iamObjectCommands`. Kubernetes answers `503 iam_management_unavailable` (service accounts, providers) and `503 user_management_unavailable` (local users), durable, with a hint and no `Retry-After`. All new mutations are `primary` in the follower contract. CLI: `kudurru iam users`, `kudurru iam serviceaccounts` (`sa`), `kudurru iam identityproviders` (`idp`), single attempt, no redirect, no replay. | G12 and G21-08 required IAM writers; without them a service account on SQLite could not get a token and a provider object could only come from migration. Reusing the security owners keeps floors durable across restart and in the replication image a follower installs and promotes, so deleting or disabling an account or provider cannot be undone by recreation. Deleting the ended tokens keeps the inventory honest; the floor alone already refuses them. A second permission for token issuance keeps `serviceaccounts.write` from being a silent token mint for whatever role an account is bound to; `tokens.write` is the verb the table reserved (for v1.0) for issuing tokens for another principal; using it in v0.2 pulls that reservation forward and needs the owner's confirmation. Floors stay permanent, as grant floors are: each delete and first disable or group change adds one security row against the 4096-row cap shared with sessions, and at the cap the command answers 503 and commits nothing; pruning floors of UIDs that can no longer authenticate is left open rather than weakening the monotonic-floor rule in this package. Kubernetes keeps kubectl as its IAM writer, as for RoleBindings (D294, D364). | Kubernetes writers through impersonated apiserver writes (duplicates kubectl and would need its own floor story for service account tokens); generic `/objects` aliases for IAM kinds (rejected in D294); `PUT` with full replacement for local accounts (would force clients to resend fields they never meant to change; `PATCH` with explicit present fields and CAS instead); provisioning service account tokens into Secrets (`spec.token`) through the API (no Secret store on SQLite; refused as an unknown field); reusing `RoleBinding`'s `unavailable` key for the new refusals (not specific; the RoleBinding key is left unchanged); a groups CRUD (`/iam/groups`): local groups are account attributes, so `groups.*` stay reserved |
