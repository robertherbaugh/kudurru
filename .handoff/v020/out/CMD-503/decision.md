| D399 | Commands superseded before dispatch | Capturing again is opt-in, per command class. A command marked with `servinghttp.WithRecapture` that is refused with `serving.ErrPending` before its transaction body began, only because another commit superseded the publication its request captured, captures the current publication again (`servinghttp.Recapture`) and is dispatched once on it; every unmarked command keeps the immediate refusal of D199 and D208, exactly as before. Marked (they carry nothing derived from their first capture into the transaction): a local password sign-in (`POST /auth/login`; it proves its password in the transaction and read only the settings, which must be unchanged), a sign-out (`POST /auth/logout`; it verifies its credential again and revokes only its own session), a single whole-object write without If-Match (`PUT`/`POST` of one `DNSZone`, `DNSRecordSet`, `BlockList`, `ClientGroup`, `Policy` or `Integration` object, marked by the API with `api.RecapturableCommand`; the command reads, authorizes and admits the stored object in its own transaction), and a record upsert (`POST /zones/{zone}/records`, marked the same way and accepted by the root only for `ZoneCommandUpsertRecord`: the request is one endpoint, and the command reads the zone and the record set, merges the endpoint and authorizes the result in its own transaction). Never marked: a write with If-Match, an object delete, a record delete, a zone import, a source entries edit (bound to the incarnation its request saw, `TestServingSourceCommandRetainsOriginalRequest`), every item of a multi-item request including the first (D378 chain, `TestServingItemsFirstItemKeepsTheOriginalSource`), domain-list commands (reviewed plan, `TestServingDomainCommandRetainsOriginalLeaseAndPlan`), cache invalidation (keyring and invalidation generation, `TestServingCacheCommandRefusesOriginalAuthorityLoss`), node-local settings (`TestServingNodeCommandActualRefusesStaleAuthorityAndFinalExpiry`), import adoption (`TestServingAdoptionActualHTTPOriginalWriterProofAndLease`; a later migration step still recaptures only its own cut), cluster settings and control merges (`TestRunServeSQLiteControlSettingsRestart`), cluster activation, `join-token` and promotion (reviewed source), OIDC callbacks and browser sign-out (captured provider evidence), TSIG keys, factors, tokens, users, role bindings, IAM writers, blocking, notify, integration operations (check, preview, sync, actions, release, delete cleanup), follower-forwarded commands and signed RFC 2136 UPDATEs. The wait is bounded by 5 s or the request deadline, whichever ends first; then the answer is the existing effect-free `503 unavailable`, with `Retry-After: 1` on the object routes; that header is set only on a refusal returned before any transaction body of the request began (`servinghttp.Dispatched`, D405). A recapture is admitted only when no command of the request has dispatched, the new authority equals the original one advanced in its installed revision, the auth view has the same dependency identity, auth controls and cluster settings object, and the original raw credential verifies on it as the same principal with the same session and effective roles; the transaction then repeats its authorization and source checks. A refusal inside the body or at commit and an uncertain outcome are never repeated. Separately, every current HTTP command, marked or not, is no longer refused by a later publication of the same cut: `servinghttp.CheckWriter` uses `Publisher.CheckWriterCut`, which admits a lease whose publication was replaced by one with the same installed generation (term, revision and digest) and the same dependency identity, while the lease's own dependency cursors are current and its authority is the Store's; that publication is the same source prepared again after a Wake that arrived during its first preparation (D405; D406 does the same for forwarded commands). Background acknowledgments and the other `CheckWriterLease` callers keep the exact publication. | A same-cut republication changes no input of the command's capture, so refusing it protected nothing, and it is not a recapture: the command keeps its lease, authorization and plan. The first version recaptured in the shared command path for every command and broke seven contract tests deterministically (a stale lease answered 412 instead of 503, a rotated keyring adopted local settings, a refused cache command changed the invalidation generation, a superseded control request answered 200): those commands carry a lease, a plan, key material or a merged request into their transaction, and a newer publication must not repair them. Sign-ins and record-set writes were the measured victims (about one sign-in in eight, a record-set write after a zone write in 3 of 6 runs; the dashboard's stub test's record upsert right after its zone write, hosted at 329f26f4), and they carry nothing of the kind, so the allowance is placed at their call sites and nowhere else. Nothing was dispatched, so capturing again is not a replay. | Recapture in the shared path with an opt-out list (the first version; every new command would be recaptured unless someone remembered to exclude it); recapturing If-Match writes (a superseded write would answer 412 where the contract asks 503) or activation and `join-token` (bound to a reviewed source; rare operator commands); admitting a same-source republication without comparing the dependency identity (D406's forwarding rule: a command reads owner values from its lease, so the stricter same-cut rule is kept for it); a client retry policy on `503 unavailable` (a client cannot tell which commands are safe to send again); an unbounded wait. |
