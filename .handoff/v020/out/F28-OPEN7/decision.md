While that write is in flight the store marks the transition (`fenceInFlight`, set before the block and cleared after the attempt has published its outcome) and DNS output reads the block in its DNS form (`Store.DNSServingAuthority`, `dnsOutputBlocked`): the managed and static anchor inputs and root admission stay current, so validated recursion and zone answers continue from the served publication. Writers, protected HTTP, publication, the updater and the deny-only supervisor still read the write block itself. Only a transition of an unblocked store is in flight: a fence whose write fails leaves the store blocked for DNS too (the member cannot prove which authority it holds), and a retry of that observation does not reopen DNS while it waits. **Sampler.** With that change no SERVFAIL gap remains on a member holding valid trust after its first publication (own promotion, fence or conflict observation, fenced-to-follower install, conflict); the e2e samplers now fail on any non-validated answer, a missing answer included, from the node's first reported publication (ready or DNS-only) on, and allow only the start of a process before it has published anything (its listeners answer SERVFAIL until then; at most 5 s per sampler) and a SERVFAIL whose extended error carries the resolver's "no name server of the zone answered" wrapping a deadline (the stand-in root timed out; at most two per sampler, never two in a row, logged). **Counts.** Every root check in the managed process tests is exact: the standalone bootstrap is exactly one applied acquisition plus the raced ones the elected updater counts in the new `kudurru_root_anchor_updater_acquisitions_total{outcome}` (applied, raced, failed, refused), with none failed or refused; one per supervised start and role (D318), and one per installed settings identity; the test sends the two patches of a forwarded settings change one at a time and waits for each check, so the one-second wake coalescing can no longer merge them. **Held package.** The eleven F28-OPEN6 commits (writer services start with a managed writer that is not due; a due first step still precedes them) are carried with two conflict resolutions (test fields in serving_runtime.go, and the partitioned restart of the old primary in the promote flow); the integrated head's apparent readiness regression of a managed recursive node is not a regression (the same test fails at the base under the same load, and alternating runs measured the same time to ready).
