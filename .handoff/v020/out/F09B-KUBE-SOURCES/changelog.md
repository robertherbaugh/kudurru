### Added

- Kubernetes: UniFi inventory and VLAN/note group integrations now run on the Kubernetes store. The replica holding the Integration's Lease polls the controller and commits one private source head; every replica watches those heads, serves the committed clients to client identification and the contributed MAC members to policy groups, closes them as soon as the Integration is suspended, edited or deleted, and keeps them during an API outage only until each observation's original expiry. Keep `spec.unifi.poll` at two seconds or more on Kubernetes.
- Kubernetes: the integration administration API (`/api/v1/integrations`) and the `kudurru integrations` list, get, check, actions and observe sync commands work on the Kubernetes store. List and get answer the same on every replica from the status on the Integration. Commands run only on the replica that holds the Integration's Lease: any other replica answers 503 with that pod's name in `hint.holder` and does not forward the request, so a client behind a Service must send the command to the named pod. When no replica holds the Lease (for example a suspended instance), the 503 carries the instance's phase and reason instead. A reviewed sync whose head write was not acknowledged is resolved by rereading the head, and otherwise answered `integration_uncertain` and not repeated.
- Kubernetes: `deletionPolicy: Delete` is supported. kudurru adds the `kudurru.io/integration-cleanup` finalizer before the instance makes any provider call, and deleting the Integration removes the records its ledger shows it published, forgets its ledger and purges its source state before the object goes. Changing the policy to `Retain`, the release command or removing the finalizer by hand ends a cleanup without removing anything. A cleanup interrupted by a Lease handover and manual finalizer removal are documented but not yet qualified on two replicas.

### Changed

- Kubernetes: UniFi Integrations that publish DNS records (`spec.unifi.inventory`) are refused with reason `RecordPublicationUnsupportedOnKubernetes`, and webhook Integrations with `UnsupportedOnKubernetes`; the `DeletionPolicyUnsupported` reason is gone. A UniFi Integration that was armed for `Delete` before it gained `spec.unifi.inventory` still cleans up its local source state when deleted.
- An Integration that kudurru refuses outright, with `deletionPolicy: Delete` and no cleanup finalizer, now reports its refusal reason instead of `CleanupFinalizerMissing`.
