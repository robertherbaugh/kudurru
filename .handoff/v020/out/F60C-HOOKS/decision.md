| D379 | Tier-B hook event production, the delivery lane and negotiated roles | Root produces hook events on each hook instance's elected lease from the store's resumable change feed (DNSZone, the private ZoneState head that holds a zone's committed serial, DNSRecordSet, Integration, Kudurru) and the current writer term, read after a durable per-instance `IntegrationEventCursor` (one private object per instance, opaque positions, exact-version CAS). Every 2 s tick (the debounce) queues at most 32 events and nothing while 256 rows are undelivered or 384 exist in all; a kind with no change keeps its position until the store head is 1,024 revisions ahead, so an idle tick writes nothing (each cursor write itself advances the head); a new instance takes a baseline and reports only later changes; a cursor the feed cannot resume (the store reports it compacted past the cursor, lineage change, too new) yields one `zone.changed` per zone (`change: "resync"`) and a fresh baseline. The delivery ID is SHA-256(instance UID, topic, subject UID, version), and an existing row is skipped, so a crash between queue and cursor commit, or a status write that does not change what a topic reports, queues nothing while that row exists (after it is evicted or pruned, such a status write resends the same ID, which the peer deduplicates). Topics shipped in v0.2: `record.changed` (generation or deletion), `zone.changed` (committed serial or deletion), `blocking.toggled` (committed changes only; a timed disable running out writes nothing and is no event), `integration.error` (Ready turned False, versioned by reason and transition time) and `cluster.leader_changed`; the provider advertises exactly these. Deferred: `query.blocked`, `vip.master_changed`, `client.seen`, `client.left`. Guarantees: at-least-once, unordered across retries, versioned payloads, 24 h dead letter; a 4xx answer dead-letters and sets Degraded `EventDeadLettered` (published); a 5xx, an attempt timeout while the caller lives, or an exhausted budget retries (budget after 5 min); a fence, stop or caller cancellation leaves the row untouched. Retention, all by exact UID/RV: each drain evicts the instance's oldest terminal rows above 128, so an instance holds at most 384 rows even when its peer acknowledges promptly (under 50,000 for 128 instances); terminal rows of any owner, including a live Integration that runs no hook lease, and undelivered rows of vanished instances are pruned an hour after their deadline; cursors of vanished instances are pruned; the retention scan pages through every row and keeps only its own rows and 64 prunable ones, so no listing size stops it. Hook events are cluster-wide: every hook instance sees every namespace, so creating a hooks Integration is a cluster-level privilege until a subscription filter exists. Signing: HMAC-SHA256 of the exact body `{"topic","time","payload"}` (JSON tags frozen for `Event`, `Client`, `Network`) with the separate `hmacKey` (32 to 4096 bytes, same bound as conformance). Budget: one charge per HTTP attempt against the instance's own account (its UID). The webhook provider reports negotiated roles (`host.RoleProvider`) so the host polls only inventory peers and never treats it as a publisher. Reviewed sync and act write one `integration.sync`/`integration.act` audit row in their final transaction, as uncertain (`error`) when the effect failed but that transaction still commits. | Hooks were designed for v0.2 (design record lines 996, 1029, 1041) but nothing produced events, the unmounted lane dead-lettered on a slow answer or a busy budget and never pruned, and one Go type could not be inventory-only. The change feed is the only durable, resumable source present on the writer; a durable cursor makes restart and failover lose nothing without a baseline storm. Deterministic IDs plus a pre-queue existence check make reproduction idempotent without exactly-once claims. | Delivery rows as the cursor (baseline storm, one row per subject retained); an in-memory diff of captures (loses changes across restart and failover); a transactional outbox in every write path (touches every command, no Kubernetes equivalent); advertising all nine designed topics while producing five; treating 429 as retriable (kept permanent, as the existing test and "4xx drops" specify); a shared `webhook/all` budget account; time-only retention (unbounded rows under a prompt peer, and a store-wide listing cap that locked every instance out); following the feed bookmark on every tick (rewrites the cursor every 2 s) |
