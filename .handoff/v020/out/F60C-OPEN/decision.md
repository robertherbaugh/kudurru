| D380 | Tier-B webhook record ownership | A webhook Integration that names `spec.webhook.domains` publishes records to a peer serving the external-dns record routes (either media type); the provider implements `host.Publisher` and `host.RecoveryPublisher` and reports the publisher role only for a records peer with domains. Ownership lives at the peer in a kudurru TXT registry: one row per managed RRset at `_kudurru-<type>.<name>` (a leading `*` label becomes a `-wildcard` suffix), with the RRset's set identifier and the single value `"heritage=kudurru,kudurru/owner=<SHA-256 of [cluster ID, Integration UID]>"`. An RRset is the instance's only when its registry row carries that marker; another kudurru marker or an external-dns heritage claim (parser moved from the Cloudflare adapter to `plan.AttachHeritage`) makes it foreign; anything else is unowned; registry rows are hidden from the planner, and only rows inside the configured domains are the destination. IDs are one digest per RRset key and versions digest content plus marker. Records needs a complete list (no pagination headers, at most 32,768 rows and 10,000 RRsets). Apply rereads, requires the intent's exact Before hash, IDs and versions and an owned or absent RRset, sends one Changes body with the data and registry rows, and returns a complete receipt only when a second complete reread shows the After RRset under this instance's registry row (a delete: no RRset); a 204 without effect, a dropped registry row, a foreign change between reread and POST, a refused or unanswered POST, or an unreadable result is a partial receipt (ambiguous targets marked) that leaves the ledger pending for the host's reread-based recovery. Adjust calls the peer's `/adjustendpoints` and refuses names the peer's filter excludes and the reserved `_kudurru-` namespace. Each configured domain must be inside the negotiated filter. A records-only peer without domains has no role: `Roles` refuses it (an ordinary lease ends ProvisionFailed) while `Check` accepts it, so a Delete cleanup, which provisions and checks but never asks for roles, still removes what the instance owns. Removing every domain ends publication: the publisher role, the reviewed `publish` mode and source selection follow the spec, so the instance no longer syncs records and its owned record sets stay as under Retain until the domains are restored or narrowed, or a Delete cleanup removes them. A registry row of another owner with no data row is a claim: the snapshot names it (`RemoteSnapshot.Claimed`, inside the domains) and `plan.Input.Claimed` makes it a conflict at its name, part of the plan digest (omitted when empty, so earlier digests are unchanged). Receipts without target facts carry nil targets in both the webhook and the Cloudflare adapter, so the store's round trip leaves them equal and the ledger confirms them in the same run. No adoption for webhook peers. Root treats "Cloudflare, or webhook with domains" as a publisher for source selection, the in-transaction source fence and the reviewed `publish` sync mode, and gives non-publishers no source dependency. A negotiated-role provider with no ledger row has a local-only cleanup. The conformance command gains `--expect-endpoints-file` (`records_contain`, `records_absent`), a read probe with no retry or cleanup. | The design record promises that existing external-dns webhook providers can be sinks (research/integrations.md 888-889) and D298 forbids treating a wire acknowledgment as a publication. A companion TXT registry is how external-dns itself owns records over webhook providers, works with both media types and needs nothing from the peer beyond storing TXT rows; reread-verified receipts give the ledger the same complete/partial facts the Cloudflare adapter has. | A negotiated ownership extension that requires purpose-built peers to return row IDs, versions and owners (no existing provider implements it); trusting the 204; one ID per target (external-dns has no per-target identity, and a key-derived ID survives an update); adoption without a spec field to authorize it; a placeholder endpoint for a foreign claim (fake targets in previews); syncing an instance without domains as a publisher of nothing (the publisher role would depend on the negotiated peer and on private ledger rows, not on the spec root uses for the reviewed sync mode, and a configuration edit would delete records); refusing the removal of the last domain at admission (file and API sources have no common update hook); treating every listed row as the destination (rows outside the configured domains would all be conflicts); refusing the generic 4,096-element JSON bound for lists (a 10,000-RRset zone needs about 20,000 rows) |
