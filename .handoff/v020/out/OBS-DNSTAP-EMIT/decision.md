| D372 | dnstap emit and the raw override (V2-OBS contract 6, README contract 6) | `type: dnstap` in `querylog.sinks` runs on the D371 sink host (own bounded queue, batch, timeout, attempts) and sends `dnstap.Dnstap` messages in Frame Streams to `unix:/path`, `tcp:host:port` or `tls:host:port` (`caRef`, `certRef`+`keyRef`, `serverName`), with the bidirectional handshake (READY/ACCEPT/START, data, STOP/FINISH). Identity defaults to `node.name`, version is `kudurru/<version>`, `extra` is `status= list= upstream= client= trace=`. A local zone or local record answer is `AUTH_QUERY/AUTH_RESPONSE` (with `query_zone`), every other answer `CLIENT_QUERY/CLIENT_RESPONSE`; `types` selects them (default the four). `FORWARDER_QUERY/RESPONSE` are opt-in and approximate: kudurru does not record its upstream exchanges, so they carry the question, the rcode, the client's times and the upstream name in `extra`, no addresses. Default output follows `querylog.privacy` exactly: the message is rebuilt from the transformed event (question, header flags, rcode; never answer records; `hidden` names; the logged client address, none for a pseudonym; no port), and `nothing` sends nothing. `raw: true` is the audited override: the sink is a `querylog.RawSink`, receives a copy of each admitted event taken before the transform, and sends the query as received and the answer as the pipeline produced it (before transport truncation/padding) with the real client address and port, under every privacy mode including `nothing`. Exclusions run first and bind raw too: `querylog.exclude.*`, the health name and the built-in dig are never sent. Wire bytes exist only while the route holds a raw sink: the log observer asks the captured route (`querylog.WireRetainer`) and packs only then (copying a message with an extended rcode first), the collector copies the event only for such a route and clears `Event.Wire` before the primary sink, the tail and every other sink. Admin-only: a settings change of `querylog.sinks` or of any `querylog.exclude.*` key that leaves a raw sink in place needs the new permission `querylog.raw` (only `admin` holds it through `*.*`) besides `settings.write`; the API checks and audits a refusal, audits the accepted change as `querylog.raw` with the raw sink names before and after, and the complete SQLite runtime re-authorizes `querylog.raw` against the original credential inside the commit transaction (`currentCommandAlso`). Turning raw off or removing the sink needs only `settings.write`. Every node records `querylog.raw.export` (actor `System/query-log`, resource the sink) before a raw sink opens, so a raw sink from the settings file or a ConfigMap is audited too; a sink whose audit event is not recorded does not open (no connection), and the host retries the open with backoff. A batch is written whole on one connection: nothing written (no connection, refused handshake, write failed before its first byte) is `Retryable`, a partial write is an unknown outcome and dropped, and the next batch reconnects; a pre-write zero-deadline read detects a collector that closed. Protobuf and Frame Streams are hand-written (about 400 lines in `internal/querylog/sinks/dnstap`); tests decode the framing with an independent strict Frame Streams reader in `dnstaptest` (written from the fstrm description, importing nothing from the sink, pinned to hand-written golden bytes) and the payload with a strict `protowire` parser and with `dynamicpb` against a descriptor of `dnstap.proto`; `test/fuzz` fuzzes the encoder and the frame reader. | The research plan (§2.6, §11.3) puts raw outside the privacy modes; contract 6 asks for an explicit admin-only, audited switch with defined behavior for hidden fields and exclusions. Exclusions are the operator's statement that a client or domain must never be logged anywhere, which raw does not override; the privacy mode is the default for consumers that did not ask for more. A separate permission keeps raw admin-only even if custom roles ever grant `settings.write`; it covers the exclusions too, because clearing one widens the raw export as much as adding the sink, and the per-node audit covers settings that never pass the API. Retaining wire only for raw routes keeps the F20d/F63 hot path unchanged (one interface assertion per query).
