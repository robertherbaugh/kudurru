| D389 | Client-ID propagation through the dnsdist edge | With `edge.clientIDDomain` (`--client-id-domain`) and/or `edge.clientIDs` (`--client-ids`), both renderers emit one `LuaAction` rule (`kudurru-client-id`, after the shared-secret rule, before pool routing) whose function derives the ID exactly as a kudurru listener does (`internal/clientid`): one DNS label before the suffix in the DoT/DoQ server name, case-folded with any trailing dot dropped, or one path component after a DoH/DoH3 path. It sends the ID in PROXYv2 TLV `0xE1` and sets `skipCache` on that query. With path IDs on, the DoH frontend stops exact path matching and the rule answers HTTP 404 for empty, extra, escaped or invalid components, as kudurru does. The trust rule is unchanged: the backend honors `0xE1` only from a listed peer that also sends the valid `0xE0` secret, even on loopback, so topology validation refuses client IDs without `proxyProtocolSecretFile`. | dnsdist's static rules (`SNIRule`, `HTTPPathRule`) cannot enumerate IDs, so the edge needs a per-query function. Sending the label as the backend expects it keeps one parser authoritative, and the backend still rejects bad labels. Edge packet caches have no client key; backend eligibility already refuses caches for clientID matchers ("client-scope"), and the skip makes an ID-carrying query safe even if a cache is attached. The secret requirement keeps the trust boundary of D45/D56: a client cannot forge an ID it could not already select with SNI or a path. | Trusting `0xE1` from listed peers without the secret (spoofable by any host in `proxyProtocolFrom`'s ranges); rendering IDs on edges without a secret (the backend would drop every such query); forwarding the raw SNI/path and parsing it on the backend (a new TLV contract and a second parser on the query path); varying the packet-cache key per ID (not supported by dnsdist 2.1.3 caches); FFI actions (more code for a rule that only runs when the option is on). |
