| D397 | Inventory read API and DHCP lease MACs | `GET /api/v1/inventory` (new permission `inventory.read`: auditor, operator, admin; not viewer) lists every inventory device, including ones that never queried, with source, MACs, names, tags, observation/expiry, `stale`, and per-address arbitration state (assigned, expired, ambiguous, superseded with the owning source/ID, withdrawn) computed by `inventory.Snapshot.Devices` from the same claim map `Lookup` uses. It reads the request's original serving cut on the complete SQLite runtime and the shared producer holder on Kubernetes, and adds the answering node's bound DHCP leases as devices with source `dhcp/<scope>`. Every lease store snapshot now also publishes all bound leases (address, MAC, client hostname, expiry), with or without a DNS name or `registerDNS`; the identify stage fills the query's MAC from the live lease of the source address only when the captured inventory supplied no MAC, clears the inventory source so source-bound private grants never match a lease MAC, and fills nothing when two scopes lease the address to different MACs. The lease snapshot is process-local: every Kubernetes replica watches all leases, but on a SQLite cluster a lease MAC applies only to queries answered by the node serving that scope, so operators who need cluster-wide effect use an inventory integration or `ip`/`cidr` matchers. A same-poll UniFi collision (two clients, equal observation time) reaches the inventory as a tied claim on each claimant, so it is listed as ambiguous and no older claim of another source can win it; records, names and groups still exclude the address. The block page `PolicyFinder` still identifies by address only. CLI: `kudurru inventory`. | MAC matchers matched nothing without an integration, and never on Kubernetes; nothing exposed devices that had not queried. Lease snapshots are already committed immutable memory read per query for hostnames, so the fill adds no store, SQL or leader dependency to the DNS path and works on both drivers. DHCP leases are not inventory observations (no observation time, lifetimes beyond the 24-hour inventory bound, node-local and frequent), so they are projected into the same device model rather than written into the replicated inventory state. MACs and device names are the sensitivity class of `dhcpleases.read`, which the viewer role also lacks. | Writing leases into the replicated inventory as a `dhcp` source (durable churn per lease event, breaks the 24-hour observation bound); reusing `clients.read` (viewer would see MACs); letting lease MACs override or merge with inventory MACs (would let a lease satisfy a source-bound grant); a dashboard-only view without an API |
