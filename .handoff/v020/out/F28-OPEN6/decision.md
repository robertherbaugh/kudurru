| D369 | Managed root anchors under enrolled HA: writer readiness, a conflicted member's own zone, and bounded proof of offline recovery (F28-OPEN6; extends the D369 row) | **Writer readiness.** A writer episode on a node whose committed image already carries an accepted managed owner that is not due for a refresh (by the updater's wall clock, with a one-minute margin and the checkpoint rule of the step) releases the elected startup gate at once, so the services that admit writer commands (primary driver, providers) start with the anchor child instead of after its first step, which then only captures and schedules; a startup write that races that capture refuses only the capture and a new one follows. Before the bootstrap, and whenever the committed refresh is due, the first anchor step still precedes those services: its reply may be a REVOKE, and a revocation denial that an ordinary commit rolls back is terminal for the writer term (anchorUpdateRaced; releasing early there left a restarted writer's first-step REVOKE uncommitted 3 of 3 in review). This removes the anchor-step wait for the usual restart, promotion and resolution; it does not make readiness imply writer admission: readiness depends on publication only, so a due writer, and the short start of the writer services on any writer, can still answer 503 while ready (left to CI-RED-2 and CI-RED-3). A capture-phase race keeps its own consecutive count; its one-second pace is deliberately not backed off (a capture is a local read; on a fresh node the bootstrap it delays is what lets the node publish), and its warning is logged at powers of two of the count. **Conflicted member's zone.** A primary that becomes Conflict or Fenced after the committed-status writer wrote its zone's status and before the driver realigned the lifecycle receipt can never realign (a DNS-only node commits nothing); its zone answered SERVFAIL indefinitely under the exact-resourceVersion serving rule. The status-only receipt rule of 6780f27d (serving readiness ignores a resourceVersion-only difference) is the fix; a mounted Conflict restart over that durable state pins it. **Bounded HA-4 proof.** A `-tags licensetest`-only seam, `KUDURRU_TEST_ANCHOR_UPDATER_AHEAD`, moves one process's writer-updater wall clock ahead for its due and checkpoint comparisons only, so the separate-process offline recovery test reaches the primary's committed RFC 5011 refresh without the one-hour wait and runs in the default e2e suite; samples, receipts and stored state keep the real clock, and a default build has no seam (`TestDefaultBuildHasNoAnchorUpdaterWall`). `KUDURRU_ANCHOR_SOAK=1` still runs the same test with production timers. | A ready node that refuses writes misleads every client and the e2e harness, so the anchor step should not hold the writer services when it cannot acquire; when it can, a lost revocation is worse than a bounded 503 window, and retrying a rolled-back revocation denial would replay an authenticated input that closed the anchor source. Making readiness wait for the anchor step would hold a node that serves valid trust unready for up to 30 s per term change. The status-write defect is a property of the zone readiness rule, not of anchors; fixing it in the anchor layer would duplicate 6780f27d. The seam changes no production timer (D297 stands) and exists only in the test-tagged binary that the process tests already use for the license key. | Releasing the gate on every managed writer (a due REVOKE became terminal); making a rolled-back revocation denial retryable (replays a refused input, contradicts the existing terminal rule); making the node report not-ready until the first anchor step (longer outages on every promotion and restart); a backed-off capture retry (kept a fresh node unready for many seconds under race); shortening `MinRefresh` or a runtime flag in release builds (changes D297 semantics for operators); fixture SQL that rewrites the committed refresh (bypasses the code under test); keeping HA-4 soak-only (no repeatable proof). |
