Lane `dash`, base `329f26f4`.

What now happens.

**(1) Served record rows of a non-default namespace.** On the complete SQLite runtime `GET /zones/{zone}/records` lists the served zone. Its rows used to name no record set, so Edit on a served client-group view of a non-default namespace saved into `default/api-<zone>` (`kids/lan` was written as `default/lan`), and an edit of any served row held by another record set added a second endpoint the builder refuses as Duplicated. A served row now names its record set, manager, set identifier, comment and labels when exactly one live (not disabled, not expired, not `public`) desired endpoint of the request's captured objects (`ZoneReads.ZoneObjects`, the same request lease as the served model) has its owner, type and view, a view looked up only in its ClientGroup's namespace (`internal/api/zones.go` `servedOwners`). System data (SOA, apex NS), dynamic data (RFC 2136 UPDATE, DHCP) and an endpoint held by several record sets name none; a desired apex NS is refused by the builder and a static endpoint reserves its name and type against UPDATE, so a proven row's served RRset holds only that endpoint's data. The dashboard edits a served row in the record set it names, keeps a view row's namespace when it names none, and withholds Edit (with the reason) from a served row that names none; Delete of a named row is limited to that record set, otherwise to the group's namespace (view) or the zone (default data). `remapView` no longer turns a bare group name into another namespace's group when the record set's namespace is edited in place. The zone guide (`docs/guide/dashboard/zones.md`) and `docs/architecture/zones.md` say so.

**(2) The list says which list it is.** `GET /zones/{zone}/records` answers `ZoneRecordList` with `source: desired | served`; `listsServed` reads it instead of inferring it from empty record sets.

**(3) CLI.** `kudurru records add --view public|<group>` stores `kudurru.view` (`--view -` is refused); `records rm --view -|public|<group>` removes one view; an explicit `-n` narrows `rm` to that namespace's record sets (without `-n` it still spans every namespace); `records list -o wide` has a VIEW column. The CLI reference is regenerated (in `329f26f4`).

**(4) Service account tokens.** A service account row has **Tokens…**: `GET /auth/tokens?all=true` (one unpaged list) filtered to that account by owner kind, namespace and name, each token revoked after an in-dialog confirmation with one `DELETE /auth/tokens/{id}` through `useIamCommand` (sent once, locked after a refusal or an unknown outcome). Listing needs `tokens.read`, revoking `tokens.delete`; `useCannotReason` adds static mode (the route's `read_only`) and the follower rule (`deleteToken` is forwarded).

**(5) Multi-subject role bindings.** The form edits every subject (up to 256) in stored order, adds and removes subjects (each in a `FieldGroup`), and refuses an empty list or a duplicate before sending; the multi-subject refusal on the row and in the dialog is gone.

**(6) Managers of accounts.** `GET /iam/users` and `GET /iam/serviceaccounts` carry `managedBy` on both runtimes (also the create and update answers of a local account). Accounts and service accounts of another manager show their change actions disabled with the reason; the dialogs' own check and the server's 409 stay.

**(7) RPZ polling.** A settling feed read keeps 3 s for two unchanged reads, then 6, 12, 24 s and 30 s (`rpzSettlingDelay`). A change of a feed's state, serial or reason, or of the error, restarts the fast reads, and so does a list or source change: the review found that d99ee061 restarted only on a changed read, so a change that leaves a pending feed reading the same (a new URL) stayed at up to 30 s; the Lists page and a list's page now invalidate through `invalidateRPZFeeds`, which restarts every streak.

**(8) Integrations batch delete.** The list selects the rows the API may delete (manager allows it, not terminating) and deletes them with `POST /integrations:batchDelete`, one request per namespace, one at a time, after a confirmation naming each instance's deletion policy, as `ObjectsPage` does.

**(9) Wording.** `docs/guide/dashboard/identity.md` says exactly which rows are disabled; the role binding and token-revocation unknown-outcome text no longer names the revocation-record limit (`iamUnknownText(what, floor)`).
