| D382 | Query tracing: sampling rule and TRACEPARENT trust | An in-house tracer (`internal/tracing`) records every query while `tracing.enabled` and decides at answer time. A trace is kept when it continues a trusted edge trace, when the head sampler picked it (`tracing.sampleRate` traces per million, default 1000; OpenTelemetry's trace-id ratio rule, so every hop with the same ratio agrees), when resolution failed (the response status is upstream failure or timeout, DNSSEC bogus or an unsynced zone, or a pipeline error; the status decides, not the rcode, so refusals, rate-limit and control drops, a cached SERVFAIL and the drain SERVFAIL of the health names never count) or when it took at least `tracing.slowThreshold` (250 ms). Traces kept only by the failed or slow rule are capped at 100 in any one second per tracer, a sliding window over the last 100 keep times (excess counted as `tail_limited`); a tail trace that the full export queue drops (`queue_full`) gives its own allowance back (its keep time leaves the window, not a later trace's); sampled and edge-continued traces are not capped. The EDNS TRACEPARENT option (code 65500, `tracing.ednsOptionCode` within 65001-65534) is removed from every QUERY before any stage runs, whoever sent it. It continues the sender's trace only when the query arrived with an authenticated PROXYv2 header (`Client.ProxiedFrom`: listed peer plus shared-secret TLV, D45/D56/D72) and `tracing.acceptTraceparent` is on; a continued trace is always kept and its TRACEFLAGS are not used. Upstreams never receive client options; only a forward group with `tracePropagation: true` gets a fresh option whose parent is the attempt span, and only for a sampled trace (head sampler or continued edge trace), flags 01: the receiver reads presence as the decision, so sender and receiver follow one rule, and a trace kept later by the tail rule has no downstream link. Only kept traces stamp `trace_id` on the query row and a histogram exemplar; the root span carries the name and client only as far as `querylog.privacy` allows. Kept traces go to a bounded queue without blocking and are posted once over OTLP/HTTP protobuf (hand-written with `protowire`); a full queue or a refused batch drops and counts. | The tail rule needs the spans of every query, and the query path must not block or allocate per stage when tracing is off; with tracing on, spans and attributes go into arrays inline in the trace, so an unkept query costs two allocations (the trace and the upstream stage's trace context), measured at about 3 µs and 4.9 KB more per query, a kept one 3 to 4 µs on the query path; with tracing off the stage chain, cache stage, upstream strategies and UDP listener benchmarks match the pre-tracing commit in allocations and bytes, because `Request` keeps its 448-byte size class (the tracing fields share a word with the existing bools; `TestRequestKeepsItsSizeClass`). Presence of the option is the edge's sampling decision: dnsdist sends it only under `SetTraceAction(true)` and the pinned dnsdist 2.1.3 sends flags 00 for traced queries (live probe), so honoring the flag would drop every edge trace. Trace ids from arbitrary clients would let anyone inject or collide traces; the PROXYv2 secret is the existing authenticated edge identity. The generated OTLP package links gRPC and its gateway into a binary that has neither (D138, D260). | OpenTelemetry SDK with `parentbased_traceidratio` (head-only, cannot keep failed or slow queries without recording all of them through the SDK, and otlptracehttp pulls gRPC); honoring the TRACEFLAGS sampled bit (drops dnsdist 2.1.3 traces); trusting TRACEPARENT by source address or from any client; retrying failed exports (unbounded memory or duplicate spans); a separate trusted-peer list for kudurru-to-kudurru propagation (deferred: only PROXYv2 peers are trusted); propagating every traced query with flags 00 (a presence-reading receiver would keep everything); keeping on a bare SERVFAIL rcode (turns health probes during drain into exported traces); a calendar-second tail window (up to twice the cap across a boundary); charging the cap for traces the full queue drops (the cap would bind on traces never exported); growing `Request` past its size class (32 bytes more on every query with tracing off) |
