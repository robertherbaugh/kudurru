| D390 | RPZ feeds on the Kubernetes driver | Every Kubernetes replica runs the same `rpz.Manager` as SQLite, persisting accepted copies in `local.db` and acquiring with the stored TSIG startup source and its hot replacement (D314/D365) through a new per-feed `CaptureZoneKeys` hook, so an unsigned feed is admitted while stored keys are pending and a ring replacement wakes the manager. The blocking stage gets a Kubernetes selector (`kubeRPZ`): `policy.ListInfo` now keeps the accepted BlockList it was compiled from, so each recursive query takes the BlockLists of its own policy decision and selects them from one immutable binding of the configuration snapshot, the node's feed snapshot and the published ring. The binding is rebuilt only when one of those three installations changes; every input is an in-memory atomic read. A missing, unbound, rotated or expired feed, or a stale configuration snapshot, stays selected as an unavailable sentinel and answers SERVFAIL with EDE "not ready". The manager is not leader-only. A restart while the apiserver is unreachable cannot read the stored TSIG keys (the startup source has no local fallback), so only unsigned persisted copies are reused; a signed feed fails closed until the pod restarts with the apiserver reachable. An RPZ-only list follows the same `blocking.allowDegraded` load window as every list: with the default a just-started node filters only with the lists already compiled; `allowDegraded: false` keeps it not ready until the list is in the policy. | The CRD accepted RPZ sources on Kubernetes and promised fail-closed behavior, but no manager ran and the stage had no selector, so an RPZ-only list compiled to an empty list and the feed was silently unenforced. Kubernetes has no complete serving bundle to bind feeds into, so the binding has to start from the request's own policy decision; carrying the object in the Index avoids looking lists up in a newer snapshot than the decision. Rebuilding only on installation change keeps per-query cost at the SQLite path's `Select`. | Refusing RPZ sources on Kubernetes at admission (drops a v0.2 row on a supported driver); running feeds only on the leader and fanning out (puts a leader on the DNS path); looking the decision's lists up by name in the current snapshot (can mix two configuration generations); binding on every query (repeats credential fingerprinting per query); flushing the edge dnsdist cache on every feed installation (SQLite does not either; left as a follow-up); reusing a signed persisted copy offline by its stored credential fingerprint (would admit a credential the node can no longer verify as current; left as a follow-up). |
