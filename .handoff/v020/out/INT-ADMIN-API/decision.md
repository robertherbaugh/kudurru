| D400 | Integration administration API: manifests and Integration object writes | `Integration` becomes a kind of the generic object routes on both drivers (`/objects/integrations`, `POST /apply`, `POST /integrations:batchDelete`, `kudurru get/apply/delete integrations`), written by the same reviewed path as every other object: strict CRD validation, manager `api`, `managed_by` for file- or other-manager-owned objects, `If-Match` as an exact resourceVersion compare-and-swap, and on SQLite one current command that re-authorizes the original credential against the attributes it derives from its own read, with the store's finalizer arming (D367) and audit row in the same transaction; an enrolled follower forwards these writes as the typed object member command, while check, preview, sync, act and release stay primary-only. Two kind-specific checks are decided on the stored object the write is swapped against: a write that binds or changes `spec.credentials` (create with credentials, added, removed or changed reference), or that changes where bound credentials are presented (`spec.type`, `spec.unifi.endpoint`, `spec.unifi.tlsFingerprint`, `spec.webhook.endpoint` while credentials are bound before or after), also needs `integrations.secrets` besides `integrations.write`, and a new Integration needs the integrations license feature (`402`, re-checked at commit on SQLite); replace and delete need no license. `integrations.write`, `integrations.delete` and `integrations.secrets` leave `reserved:`. Credentials stay references: the CRD has no value field, strict decoding refuses one, reads return references only (a holder of `integrations.read` sees the reference names in use; only the unused rest of the node's allowlist is withheld by the manifests route), and a validation failure of an Integration write that names `spec.credentials` is answered with a fixed message and field paths only, while every other refusal has each `spec.credentials` string removed in its raw, Go-quoted and JSON-escaped forms, so a value pasted into a reference field (also with a newline, quote, backslash or under six bytes) is not echoed, relayed by a follower or logged. `GET /integrations/manifests` (`integrations.read`, `kudurru integrations manifests`) returns the compiled provider manifests (configuration schema, credential keys with `required`, capabilities), the driver, the only namespace that runs (Kubernetes release namespace), license coverage, the reference forms this node resolves, and per type `supported`/`reason` and the `refused` spec fields of this driver (Kubernetes: webhook unsupported, `spec.unifi.inventory`; both: UniFi push fields); the node's allowlisted file paths and environment names are included only for a holder of `integrations.secrets`. `cli.Kinds` gains Integration with `NoBackup`, so `kudurru backup` and a kind-less `kudurru export` do not start needing `integrations.read`; `kudurru export integrations` exports them. | The integration host already reads Integrations from the store on both drivers, so the object routes are the one write path whose CAS, ownership, audit, follower and current-command rules are already proven; a parallel `/integrations` CRUD would duplicate them. A credential reference can name any credential the node allowlisted for every Integration (D197, D384), so choosing one, or choosing the server it is presented to, is a capability distinct from editing what an instance publishes. The validator prints a refused value `%q`-quoted, so substring redaction alone cannot be relied on for the field it refuses. An operator must be able to suspend, retarget or remove an instance without a license (D367). Exact refusals are only useful if the form knows the driver's limits before it writes. | A dedicated `/integrations` create/replace/delete route family; inline credential values or write-only secret fields; returning no credential references at all (the object would not be re-applicable and the form could not show the binding); requiring `integrations.secrets` for every write or for reads (and hiding reference names from `integrations.read`, which would make an object unreadable for re-apply); requiring it only on `spec.credentials` changes (a writer could point bound credentials at its own server); redacting validation messages by substring matching alone; license-gating replace and delete; deriving the driver limits by probing a provider; adding Integration to the default backup set |
